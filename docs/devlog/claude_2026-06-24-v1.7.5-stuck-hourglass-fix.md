# v1.7.5 — fix tabs frozen on ⏳ after a session is done

User saw several finished tmux-in-Cursor sessions stuck showing the ⏳ hourglass tab,
and focusing them didn't fix it.

## Investigation (non-destructive)

- Read `/tmp/cc-notify/*.tab`: the files **literally contained `⏳`** for the done
  sessions → not extension staleness; the `Stop` write never landed.
- Pattern: long-running tmux sessions stuck; tiny/ended ones fine. All stuck ones
  were tmux-in-Cursor.
- `tmux list-clients`: the route ttys are still attached (so it's not a detached
  client). `cc_detect_terminal` returns `vscode` *now* — but it's flaky under tmux.
- Inspected the **deployed** code (`~/.claude/plugins/cache/farishijazi-plugins/
  cc-notify/1.7.1/hooks/cc-notify.sh`): the tab write is
  `if term=vscode && shell_pids; then cc_write_tab; fi` with **no else**
  (`cc_set_status` count = 0). Confirmed root cause.

## Root cause

Two writers, mismatched gating (see @LESSONS.md #18):
- mid-turn **⏳** comes from the **ungated** cheap path (`cc_set_status` in
  `cc-capture-window.sh`) — always succeeds.
- the **done/outcome** write on `Stop` goes through `cc-notify.sh`'s `cc_write_tab`,
  **gated on `term=vscode`** which flakes under tmux. When it flakes, the full write
  is skipped entirely and the last-written ⏳ freezes.

## Fix

`hooks/cc-notify.sh`: added an `else` fallback to the tab-write block —
`else ( cc_set_status "$sid" "$status_emoji" & )`. The cheap path has no term/pid
dependency, so the outcome emoji is always swapped onto the existing `.tab` even when
detection fails. ⏳ can never outlive the turn now.

## Immediate resync of already-stuck tabs

One-off loop: for each `.tab` whose name starts with ⏳, `cc_set_status` → (transcript
token via `cc_last_status_token`, else `ℹ️`), **skipping** sessions whose transcript
changed in the last 45s (genuinely active). Recovered real tokens: work-b-ops-ui → ✅,
spl export → 🙋, feat/miner-sublist → 💬, etc. The still-⏳ ones (rich return values,
ramp rate, work-b-ops-dashboard) proved **active** (transcripts modified seconds ago;
"rich return values" even reverted ℹ️→⏳ from a live hook) — correct, not stuck.

The user's `/plugin marketplace update` pulled the OLD `main` (1.7.1), so the bug

**new** Claude Code sessions (hook scripts load at session start). The resync only
fixed the currently-stuck tabs as a one-time band-aid.
